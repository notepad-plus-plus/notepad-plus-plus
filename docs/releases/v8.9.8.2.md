# Notepad++ v8.9.8.2 — ReCodera-AI Community Build

This community build carries focused fixes for bidirectional text rendering, document direction, and typography. It is based on the Notepad++ source maintained by the original project at [notepad-plus-plus/notepad-plus-plus](https://github.com/notepad-plus-plus/notepad-plus-plus). It is an independent community release and is not an official upstream Notepad++ release.

---

## Fixes

### Arabic and English in LTR documents
Corrected visual placement and clipping of mixed bidirectional text. Arabic retains its right-to-left reading order while Latin text remains left-to-right, including whitespace, backgrounds, and selections. The Scintilla drawing path utilizes DirectWrite visual intervals for accurate text and background segment placement.

### English and Latin Word Order in RTL Documents (Microsoft Word Parity)
When switching the document direction to RTL (`View -> Text Direction RTL` with `WS_EX_LAYOUTRTL`), Latin words, English sentences, and code tokens previously rendered with reversed word order across style boundaries (for example, `ChatGPT Work Repeatedly Stops Before Completing Tasks` appeared backwards). Implemented `ScreenLineLayoutGDI` powered by Windows Uniscribe (`usp10.dll` via `ScriptItemize` and `ScriptLayout`), mapping exact visual runs and character bounds so that English reads in natural left-to-right sentence order anchored to the right margin, providing full visual parity with Microsoft Word.

### End-of-Line Dark Strips and Trailing Background Artifacts
Corrected the visual-to-logical trailing background gap calculation in Scintilla when drawing line backgrounds with bidirectional runs. This eliminates black/dark strips, phantom gaps, and background color seams at the ends of lines across both RTL and LTR document views.

### Bidirectional Caret, Selection, and Indicator Alignment
Fully wired `IScreenLineLayout` into the GDI RTL surface pipeline. Caret positioning, mouse hit-testing (`PositionFromX`), translucent selection rectangles (`FindRangeIntervals`), and syntax/spellcheck indicators now align with pixel accuracy across both RTL (Arabic/Hebrew) and LTR (Latin/English) text runs.

### Remembered RTL direction
Each document’s display direction is restored when switching buffers, reopening files, and restoring a saved session. This preserves each file's individual RTL or LTR view setting across application sessions without cross-tab leakage.

### DirectWrite behavior
LTR documents retain the configured DirectWrite renderer. RTL window mirroring uses a compatible rendering path, then restores the configured renderer when returning to LTR.
